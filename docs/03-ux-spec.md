# 사용자 흐름 및 화면 명세

## 1. 정보 구조

- Today: 오늘 할 일, 임박 경고, 이번 주 지원
- Applications: 전체 공고와 필터
- Add: URL 분석 또는 직접 입력
- Settings: 계정, 시간대, 알림

Applications 필터는 Saved, In Progress, Applied, This Week, Expired, Archived를 제공한다. Inbox는 별도 화면 대신 Saved 필터로 통합한다.

## 2. 최초 사용자 흐름

```text
가입/로그인
→ 빈 Today 화면
→ 첫 공고 추가 CTA
→ URL 분석 또는 직접 입력
→ 확인
→ 공고 상세
→ Today에 다음 행동 생성
```

빈 화면은 기능 설명보다 `첫 공고 추가`를 중심으로 구성한다.

## 3. 공고 추가 흐름

### URL 방식

1. URL 입력
2. URL 형식과 접근 가능성 검사
3. 분석 중 화면 표시
4. 추출 결과를 편집 가능한 폼으로 표시
5. 신뢰하기 어려운 값과 미확인 값을 강조
6. 사용자가 확인 후 저장

분석 실패 시 오류 원인을 짧게 표시하고 같은 URL이 채워진 직접 입력 폼으로 이동한다.

### 직접 입력 방식

필수 필드는 회사명과 직무명이다. URL과 마감일은 미정일 수 있다. 날짜 입력에는 `날짜·시간 지정`, `상시 채용`, `미정`을 제공한다.

### 검증

- 목표일은 실제 마감일 이후일 수 없다.
- 이미 저장한 URL이면 기존 공고 보기와 새로 저장하기 중 선택한다.
- 과거 마감일이면 마감 공고임을 경고하되 저장은 허용한다.

## 4. Today 화면

상단에는 가장 급한 행동을 최대 3개, 다음에는 이번 주 공고를 표시한다.

행동 카드 정보:

- 회사와 직무
- 목표일 기준 D-Day, 실제 마감 보조 표시
- 다음 행동 한 개
- 준비 진행률
- 행동 CTA

우선순위가 같은 경우 사용자가 수동으로 고정할 수 있는 기능은 MVP 이후로 둔다.

## 5. Applications 화면

목록 항목은 회사, 직무, 기준일, 상태, 진행률을 표시한다. 기본 정렬은 임박 순이다.

지원 필터:

- 상태
- 이번 주 마감
- 마감됨
- 검색(회사·직무)

모든 필터 결과가 없으면 필터 해제 행동을 제공한다.

## 6. 공고 상세 화면

### 헤더

- 회사·직무
- 상태 변경
- 외부 공고 열기
- 수정·보관 메뉴

### 일정

- 실제 마감
- 개인 목표일
- D-Day

### 준비

- 준비 진행률
- 작업별 상태
- 작업 추가·수정·정렬

### 자기소개서 문항

AI가 추출한 문항을 읽기 전용으로 표시한다. 답변 작성 기능은 후속 범위다.

### 지원 완료

`지원 완료` 버튼은 확인 후 Applied로 변경한다. 실수로 누른 경우 상태를 되돌릴 수 있으며 appliedAt 변경 이력을 남긴다.

## 7. 핵심 상태 화면

- Loading: skeleton과 현재 작업 설명
- Empty: 다음 행동 하나와 예시
- Error: 원인, 재시도, 대체 경로
- Offline/timeout: 입력값을 유지하고 재시도
- Analysis pending: 다른 화면으로 이동 가능
- Expired: 마감됨 표시와 보관 또는 마감 정보 수정

## 8. 콘텐츠 원칙

- `관리하기`보다 `자기소개서 시작하기`처럼 구체적인 동사를 사용한다.
- D-Day만 표시하지 않고 날짜를 함께 제공한다.
- AI 결과에는 `자동 추출됨—저장 전 확인해주세요`를 표시한다.
- 위험한 삭제와 지원 완료는 결과를 명시한다.

## 9. 접근성

- 색상만으로 상태를 구분하지 않는다.
- 체크박스와 상태 선택에 텍스트 라벨을 제공한다.
- 모달 열기·닫기 시 focus를 관리한다.
- 날짜 선택은 키보드 입력도 허용한다.
- 알림과 분석 완료 상태는 스크린리더에 전달한다.
