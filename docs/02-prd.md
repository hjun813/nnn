# 제품 요구사항 명세서(PRD)

## 1. 우선순위 정의

- P0: MVP 출시 필수
- P1: 출시 직후 가치 또는 안정성을 크게 높임
- P2: 후속 확장

## 3. 다음 행동 규칙

1. Applied, Archived는 제외한다.
2. Expired는 행동 목록 대신 마감 경고 영역에 둔다.
3. 기준일은 목표일이 있으면 목표일, 없으면 실제 마감일이다.
4. 기준일이 가까운 공고가 우선한다.
5. 같은 기준일이면 실제 마감일, 생성 시각 순이다.
6. 작업이 모두 준비되면 `지원하기`를 반환한다.
7. 아니라면 In Progress 작업을 우선하고, 없으면 sortOrder가 가장 낮은 Todo 작업을 반환한다.
8. 작업이 없으면 `필요 서류 확인하기`를 반환한다.

## 4. 비기능 요구사항

- 주요 페이지의 일반 조회 응답은 서버 기준 p95 500ms 이내를 목표로 한다.
- 분석 작업은 30초 이상 걸릴 수 있으므로 상태 조회가 가능해야 한다.
- 모든 쓰기 API는 인증과 리소스 소유권을 검증한다.
- 저장 시각은 UTC, 표시는 사용자 시간대를 사용한다.
- 공고 URL과 메모는 출력 시 안전하게 이스케이프한다.
- 핵심 변경에는 구조화 로그와 요청 추적 식별자를 남긴다.
- 모바일 360px 이상과 최신 데스크톱 브라우저를 지원한다.
- 키보드 조작, 명확한 focus, WCAG AA 대비를 목표로 한다.

## 5. 분석 이벤트

`sign_up`, `job_create_started`, `job_created`, `analysis_requested`, `analysis_completed`, `analysis_failed`, `analysis_confirmed`, `task_status_changed`, `application_status_changed`, `application_applied`, `job_archived`, `notification_opened`를 기록한다.

이벤트에는 userId의 분석용 비식별 키, jobId, 발생 시각, 이전·이후 상태를 포함하되 공고 원문과 자기소개서 내용은 기본 분석 속성에서 제외한다.
