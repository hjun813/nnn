# 의사결정 기록

구현 중 결정이 바뀌면 기존 내용을 지우지 않고 상태와 근거를 갱신한다.

## ADR-001 모듈형 단일 애플리케이션

- 상태: 제안
- 결정: 웹·API는 하나의 애플리케이션으로 시작하고 분석 작업만 비동기 경계를 둔다.
- 이유: 초기 운영 복잡도를 줄이면서 느리고 실패 가능한 수집을 분리할 수 있다.

## ADR-002 수동 등록 우선

- 상태: 승인
- 결정: AI 없이도 전체 지원 흐름을 사용할 수 있게 한다.
- 이유: 외부 페이지 수집 실패가 핵심 제품 사용을 막아서는 안 된다.

## ADR-003 준비 진행률과 지원 상태 분리

- 상태: 승인
- 결정: 작업 진행률은 준비 정도만 나타내며 Applied는 별도 상태로 유지한다.
- 이유: 모든 서류가 준비돼도 실제 지원하지 않은 상황을 정확히 표현한다.

## ADR-004 날짜 저장

- 상태: 승인
- 결정: 시각은 UTC로 저장하고 원문 시간대·사용자 시간대를 보존한다.
- 이유: D-Day와 알림 계산의 일관성을 확보한다.

## ADR-005 AI 결과 확인

- 상태: 승인
- 결정: AI 분석은 초안이며 사용자의 명시적 확인 후 공고를 생성한다.
- 이유: 잘못된 마감일은 사용자에게 중대한 손실을 만들 수 있다.
